## 系统概述

本项目是基于 NautilusTrader 平台的套利系统扩展，用于 Polymarket 和 OrbitExch 的跨平台套利交易。

## 服务模块详情

### 1. Market Discovery（市场发现）

**路径**: `services/market_discovery/`

**职责**:
- 从各平台 API 获取市场/事件数据
- 解析并标准化数据格式
- 持久化到 JSON 文件

**组件**:
| 文件 | 说明 |
|------|------|
| `polymarket_final_v3.py` | Polymarket 数据爬取 |
| `orbitexch_crawler.py` | OrbitExch 数据爬取 |

### 2. Market Matching（市场匹配）

**路径**: `services/market_matching/`

**职责**:
- 跨平台市场匹配
- 识别相同或相似的交易市场
- 生成匹配结果供套利分析

**组件**:
| 文件 | 说明 |
|------|------|
| `market_matching_service.py` | 匹配服务主入口 |
| `config.py` | 配置管理 |
| `matchers/` | 匹配算法实现 |

### 3. Market Data（市场数据）- 计划中

**职责**:
- 实时市场数据订阅
- 数据流处理和分发

### 4. Arbitrage（套利策略）- 计划中

**职责**:
- 套利机会识别
- 策略执行决策

### 5. Execution（订单执行）- 计划中

**职责**:
- 跨平台订单执行
- 持仓管理

## Web Panel 架构

## 技术决策记录

### ADR-001: 使用 JSON 文件作为中间存储

**状态**: 已采纳

**背景**: 需要在服务间传递市场数据

**决策**: 使用 JSON 文件而非数据库

**理由**:
- 简化开发和调试
- 数据量适中，无需复杂存储
- 便于人工检查和修正

**后果**:
- 不支持高频更新场景
- 需要后续迁移到数据库

### ADR-002: Web Panel 使用 FastAPI

**状态**: 已采纳

**背景**: 需要提供 Web 界面进行配置和监控

**决策**: 使用 FastAPI + Jinja2

**理由**:
- 与现有 Python 技术栈一致
- 支持异步操作
- 开发效率高

## 扩展点

### 添加新平台

1. 在 `services/market_discovery/` 创建新爬虫
2. 实现数据标准化接口
3. 在 `market_matching/` 添加匹配规则
4. 更新 Web Panel 配置界面

### 添加新匹配算法

1. 在 `services/market_matching/matchers/` 创建新匹配器
2. 注册到匹配服务
3. 配置启用/禁用选项
