## 审查清单

### 1. 代码质量维度

| 检查项 | 权重 | 评分标准 |
|--------|------|----------|
| **命名规范** | 10% | 变量/函数/类命名清晰、一致 |
| **代码结构** | 15% | 函数长度适中、职责单一 |
| **错误处理** | 15% | 异常捕获完整、错误信息有用 |
| **注释质量** | 10% | 必要注释、中文描述清晰 |
| **代码复用** | 10% | 无重复代码、合理抽象 |

### 2. 测试覆盖维度

| 检查项 | 权重 | 评分标准 |
|--------|------|----------|
| **单元测试** | 15% | 覆盖率≥80%、边界条件覆盖 |
| **测试质量** | 10% | 断言有效、测试独立 |
| **测试数据** | 5% | 数据合理、覆盖场景 |

### 3. 架构一致性维度

| 检查项 | 权重 | 评分标准 |
|--------|------|----------|
| **模式遵循** | 10% | 符合既有架构模式 |
| **接口契约** | 10% | 接口定义清晰、向后兼容 |
| **依赖管理** | 5% | 依赖合理、无循环依赖 |

### 4. 风险评估维度

| 检查项 | 权重 | 评分标准 |
|--------|------|----------|
| **性能影响** | 10% | 无明显性能问题 |
| **边界条件** | 10% | 边界情况处理完善 |
| **回滚方案** | 5% | 有回滚/迁移方案 |

---

## 评分计算

### 综合评分公式

```
综合评分 = Σ(维度评分 × 权重)
```

### 维度评分标准

| 评分 | 描述 |
|------|------|
| 90-100 | 优秀，无明显问题 |
| 80-89 | 良好，有小问题可改进 |
| 70-79 | 合格，需要修改 |
| 60-69 | 勉强，需要重大修改 |
| <60 | 不合格，需要重写 |

---

## 决策规则

### 主AI 决策矩阵

| 综合评分 | Codex 建议 | 主AI 决策 |
|----------|------------|-----------|
| ≥90 | 通过 | **直接确认通过** |
| 80-89 | 通过 | 仔细审阅后决策 |
| 80-89 | 需讨论 | 仔细审阅后决策 |
| <80 | 退回 | **直接确认退回** |
| 任意 | 需讨论 | 仔细审阅后决策 |

### 例外情况

主AI 可推翻 Codex 建议，但必须：
1. 记录推翻原因到 `operations-log.md`
2. 说明技术依据
3. 承担后续风险

## 常见问题检查清单

### 必须检查

- [ ] 是否有硬编码的配置值？
- [ ] 是否有未处理的异常？
- [ ] 是否有潜在的性能问题？
- [ ] 是否有重复代码？
- [ ] 是否有遗漏的边界条件？
- [ ] 测试是否覆盖主要场景？

### 建议检查

- [ ] 变量命名是否清晰？
- [ ] 函数是否过长（>50行）？
- [ ] 是否有过深的嵌套（>3层）？
- [ ] 注释是否与代码一致？
- [ ] 是否使用了魔数？

### 严重程度定义

| 级别 | 描述 | 处理要求 |
|------|------|----------|
| 🔴 阻塞 | 必须修复才能合并 | 立即修复 |
| 🟡 警告 | 强烈建议修复 | 本次修复或创建 TODO |
| 🟢 建议 | 可选改进 | 自行决定 |
