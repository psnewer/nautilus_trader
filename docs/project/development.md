# 开发方法与项目里程碑

## 开发准则

### 整体局部原则

设计与编码工作遵循整体局部原则：

| 层级 | 文档位置 | 作用 |
|------|----------|------|
| **整体** | `docs/project/*.md` | 系统级需求、架构、数据库设计 |
| **局部** | `src/*/requirements.md`、`src/*/architeture.md` | 模块级需求和设计 |

在分析各模块下的 md 文件时，应联系 `docs/project/` 下的整体说明文件和关联模块下的说明文件。

### 需求驱动开发

开发流程均由需求触发，遵循以下流程：

```
需求定义 → 架构设计 → 架构审查 → 编码实现 → 测试验证
```

1. **需求触发架构**：新需求首先触发架构设计
2. **审查通过触发编码**：通过审查的架构设计再触发编码和测试流程
3. **变更同步**：需求变更需重新评估架构影响
